# 从检测报告反推检测器在测什么

手上有一份 AIGC 检测报告（知网/维普/朱雀/PaperPass），问题不是"怎么改得像人写的"，而是"它到底对什么敏感"。这份 skill 把报告里的标色重新算一遍，用数字判断哪些改法有证据、哪些是流传的说法。

不适合：没有报告、只想让文字自然一点 → `humanizer` / `academic-humanizer`。想判断稿子本身有没有内容 → `ai-draft-quality-screen`。这份 skill 只管检测器行为，不管学术诚信判断。

## 三条不许违反的

1. 只推断"对什么敏感"，不推断"想抓什么"。写"某模式下这些段落被标显著"，不写"系统认出了 AI 腔"。
2. 每条推断带置信度（高/中/低）和**可被什么新证据推翻**。没有推翻条件的不是推断，是口号。
3. 效果只写"基于证据 X 的预期"。没有复测就没有结论，报告里如实写没有。

## 流程

### 0. 先判报告能不能反推

可反推的报告必须同时有三样：字符级标色（红=显著、橙/黄=疑似）、片段表（字符数+标签+占比）、全文 AI 特征值。

只有片段表、没有标色的，最多做到片段级，**不要**拿片段表倒推句式特征——那样得到的结论无法与"块边界怎么切"分离。

### 1. 把颜色流抽出来

```bash
python scripts/reconstruct_markup.py 报告.pdf --colors      # 先看调色板
python scripts/reconstruct_markup.py 报告.pdf -o data/labeled_lines.jsonl
```

坑按踩过的顺序：

- 这类报告的 PDF 字体没有 CMap，`pdftotext` 只吐数字和拉丁字母，中文全丢。必须用 PyMuPDF 读 span 的 `color` 字段。
- 颜色是整型 RGB。知网 2026-11 版：正文 `#404040`、显著 `#E60111`、疑似 `#D99E4C`。换厂商或换版本颜色会变，所以先 `--colors` 打直方图再映射。
- 三类噪声必须剔：20pt 以上的水印、左侧 bbox 右边界 <95 的竖排栏、页眉页脚（`cx.cnki.net`、`知网个人AIGC`、`— 12 —`）。混进去游程边界就全错。

核对：脚本会打出显著字符数与占比，以及最长的几个游程。用它们对报告首页的 AI 特征值和片段表：

- 游程数与片段数应一致（案例：19 对 19），单个游程比报告的片段字符数少 10–90 字是正常的（空白与版面条目不计入）。
- 占比不会与报告首页完全一致（案例：清理后的流 42.6%，报告首页 40.2%），因为报告的分母含页眉页脚。**不要为了让两个数相等去调阈值**，按片段逐个核对更可靠；差 5 个点以上才是颜色映射错了。

### 2. 三个数先核一遍

1. 全文 AI 特征值 = 显著字符 ÷ 总字符，疑似进分母不进分子；分节值同法算，**全文值不是分节平均**。
2. 报告里的几个"部分"往往是字符四等分，不对应章节（案例：9012/10878/10222/9449 合计 39561，对应九个章节）。硬数据，可以直接写进交付物。
3. 报告给的每段占比 × 该部分字符数，应与片段字符数对得上。对不上说明分子分母口径不同，后面所有加法都得重来。

### 3. 按文本类型分池

```bash
python scripts/report_stats.py --data data/labeled_lines.jsonl
```

要看的不是总分，是"同样长度、不同类型分别多少被计"：

| 类型 | 案例 |
|---|---|
| 中文论述散文 | 60.0% |
| 小标题 | 49.5% |
| 表注（"注：…"） | 29.5% |
| 表体/算式行 | 27.8% |
| 英文/参考文献 | 3.1% |
| 纯数字行 | 0.0% |

这张表通常一步就能解释"为什么后二十页干净"：不是因为那里写得像人，是因为那里全是数字与文献。

措辞上必须区分两件事：表格**进了分母、几乎不进分子**，≠"表格不被检测"。后者会被第二篇表格很多的论文推翻；前者是可算的。

### 4. 块级检验，破掉没证据的句式理论

`report_stats.py` 第二段：按连续同标签切块，对纯中文散文块算 7 个特征（数字密度、序数并列、括号、连接词、限定词、平均句长、句长标准差），3000 次置换检验。

案例结果：数字密度 p≈0.05、限定词 p≈0.03 边缘可区分；序数并列 p=0.41、括号 p=0.99、连接词 p=0.41、平均句长 p=0.36、句长标准差 p=0.22 全部不显著。

由此得到的三条，比任何单条结论都重要：

- **套话式"AI 特征"（序数并列、括号统计量、句长均匀）在这份报告里不区分标红。** 它们是第三方文章与"降 AI 工具"的说法，不是检测器行为。
- **块级与句级的符号可以相反。** 案例里标红块数字更多（9.07 vs 5.13/百字），但标红句数字更少（p=0.015）。出现反向就把该特征的对策降级为"待验证"，不许写成结论。
- **p 值随切块阈值动。** 换个阈值块数从 61 变 62，p 就从 0.039 漂到 0.050。所以 p 值只用于"有没有方向"，不要当稳定性证据引用；未标块少于 5 个时检验力不足，置信度上限是"中"。

### 5. 推断清单

每条写四样：陈述 / 支撑证据编号 / 置信度 / 推翻条件。少于 8 条、或全是"中"以下，就在交付里直说证据不够。

格式见 `references/cnki-case.md`（10 条推断的完整写法）。

### 6. 对策按证据强度分层，不按"听起来有用"排序

- **有硬证据、效果可算的**：把成串数值从散文搬进表格（字符从 60% 的池子挪进 0% 的池子，下降按搬走的字数等比例估）。参考文献与英文摘要保持原样。
- **结构合理但样本只有一两个的**：压缩 800–2600 字的纯论述块、表注移进表体、摘要按"结论—证据—边界"重排 —— 一律标"待验证"。
- **无证据甚至方向相反的**：长短句交错、插入语设问、堆限定语、通用同义词替换。案例有反方向数据（标红块限定词更多、句长更起伏、词级改动改不了块级判定），直接写"不推荐"并给出理由。
- **禁止清单**：翻译成英文规避、标点扰动、整篇口语化、批量工具改写不复检、拆段到 300 字以下（案例标红块最短 71 字，块长与标红无阈值）。

每条对策要带：针对的推断编号 / 操作（改什么、不改什么）/ 预期（可算就写算式）/ 反例边界 / 验证方式。

### 7. 交付里必须写"这次不能说明什么"

- **单篇单系统不外推。** 只有知网一份报告，就不给维普/朱雀/PaperPass 的结论。
- **没有复测就没有效果数据。** 给最小复测方案：只改一段 → 同一版本重测同一 PDF → 比三个数（全文特征值、片段数、该段标签）。三者都不变，对策降级。
- **字数账要算给用户看。** 案例试改后多 71 字（+18%），若那段仍被判显著，等于多送 71 个分子。这是负收益，不是"更规范"。
- **二手数字只作方向。** GitHub 上"20.6%→10.1%"这类只有结论没有原件的，不能证明量级。

## 交付物

1. 证据表：来源类型 / 系统 / 片段特征 / 内容特征 / 可信度 A–C
2. 推断清单：陈述 + 证据编号 + 置信度 + 推翻条件
3. 对策手册：推断编号追溯 + 预期 + 反例 + 验证
4. 一段试改对照：改前 / 改后 / 逐处依据与风险
5. `data/` 中间产物：`labeled_lines.jsonl`、`fragments.csv`、`type_shares.csv`、`blocks.csv`。**任何数字都要能被脚本重算，不手抄。**

## 别做的事

- 不把"显著→疑似"当降分证据：疑似不计分，但标签漂移也可能只是块边界在动。
- 不为了降分损害论证。案例里标红最狠的正是贡献段与文献综述——改坏代价最高。
- 不把第三方规则清单（humanizer-zh-academic、antislop-cn 之类）当检测器事实，它们是对策方的假设，只能作假说来源。
- 引用检测器版本要谨慎：同一轮升级在卖方内容里能写成"4.0"和"第五代"两个版本号，这种数字不引用。

`pip install pymupdf`（只有这一步需要第三方包，其余全是标准库）。
